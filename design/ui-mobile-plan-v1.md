所有坐标均为**逻辑 px**，参考视口 1600×720（2400×1080 窗口，inset 0，touchScale ts=1.00）。

## 0. 先把尺度说清楚：为什么现在“挪不重叠”还不够

**物理换算（Seeker 类，2400×1080，约 414 ppi）**
- 1 逻辑 px = 1.5 物理 px。
- 1 dp = 414/160 ≈ 2.59 物理 px ≈ **1.73 逻辑 px**。
- 推论：
  - 48 dp 的最小触控目标 ≈ **83 逻辑 px**。
  - 12 sp 正文 ≈ **21 逻辑 px**。
  - 10 sp（手机上可读的下限）≈ **17 逻辑 px**。
- `_phone_factor()` = 1.925（`world.gd:11514-11526`）。按定义，“设计 px × 1.925 ≈ 1.1 dp”，所以 s=1.925 才是手机该有的放大倍数。

**现状的病根（代码实测）**
- **顶行**被压到 s_top。`_layout_hud` 把 [hero 466 | 卡 726 | 小地图 176] = 1368 设计 px 硬塞进一行（`world.gd:11699-11700`），所以 s_top = (vw−24)/1368：
  - 2400×1080：**1.152**
  - 2340×1080：**1.123**
  - 1920×1080：**0.918**（比桌面还小）
- 顶卡里的 11 px 字（区域/档/天气片 `:2823-2831`、钱包数字 15 px）在 2400 上画出来约 12.7 逻辑 px ≈ **7.3 sp**，在 16:9 机上 ≈ 5.8 sp。**这不是重叠问题，是信息密度问题**：一行塞了 PC 的全部信息，只能缩小。审计报告里的 s_top=1.229 是 F7 加宽之前的值，加宽后更小了。
- **模态框按 4:3 设计**，在 20:9 屏上靠高度裁切缩放：`_apply_ui_scale` 的 fit clamp 用的是 min(s, 0.96·vp/size)（`:11566-11567`）。
  - 暂停 780×540 → 1.28，“继续”大按钮 52×1.28 = 67 逻辑 px ≈ 39 dp。
  - 设置 740×570 → 1.21。
  - Loadout 1090×636 → **1.087**，11–12 px 字画出来 ≈ 7 sp，见 `loadout_2400x1080_s100_fixed.png`。
- **主菜单在手机上根本没放大**：`_menu_panel` 是 FULL_RECT（`:3477`），`_register_one` 只登记 anchor 点状的节点（`:11543`），所以整个菜单（标题除外全是 13–19 px 字）在手机上是 s=1。见 `settings_hud_2400x1080_s100_fixed.png` 背景里的初始伙伴卡。
- **左下 BL 簇**设计宽 460（`:3106`），× s 1.925 = **885 逻辑 px**，占屏宽 55%。其中：
  - 4 个物品槽**从未填充**（`:3111-3117`，节点没有存引用）；
  - 触控模式下 ult 圆和名字隐藏（`:10515-10521`），留下 352–444 一段空位。
  - 这是 prompt 在 1920×1080 / ts 1.50 只剩约 38 px 跨度的根因（`:11875-11885` 的注释自己也承认“Real relocation = C22”）。

结论：要做的是**重新分层（什么必须常驻、什么一次点击可达）**，然后让常驻层拿回足够的缩放。

## B. 手机适配规划

### B0. 设计原则（每条都落到可测的数）

1. **拇指热区（横屏）**
   - 左下（摇杆）和右下（动作）是**免费区**，放高频操作。
   - 顶部两角是**昂贵区**，只放低频、误触代价高的操作（暂停、大地图），或者只读信息。
   - 中间是**游戏画面**。
2. **战斗可扫读**
   - 中央矩形 x∈[0.30·vw, 0.70·vw]、y∈[0.42·vh, 0.85·vh]（玩家角色和近战区）里**常驻元素为 0**。
   - 允许的瞬时元素：中央栈（boss / 迷你条 / toast）只占 y ≤ 0.55·vh 的上部；prompt 气泡只贴底。
3. **渐进展开**
   - 常驻层只放战斗必扫项。
   - 其余一律放到**一次点击可达**的地方（暂停“状态”页、目标抽屉、大地图）。
   - **不删除任何玩家可见信息**。每个 COLLAPSE 项在 §B1 表里写明它的去处。
4. **触控目标**
   - 主操作 ≥ 48 dp（83 逻辑 px，ts=1）。
   - 次操作 ≥ 40 dp（70 逻辑 px）。
   - 视觉可以随 touchScale 缩到 0.7，但**命中区不小于 70 逻辑 px**（hit-slop）。
5. **字号**（画出来的大小 = 设计字号 × 节点缩放）
   - 常驻 HUD 正文 ≥ 19 逻辑 px（≈11 sp）。
   - 必扫数字（计时、HP 数、金币）≥ 24 逻辑 px。
   - 模态正文 ≥ 21 逻辑 px。
   - 低于这些值的字只能是装饰或单位符号。
6. **安全区**：所有布局数学都在 `_ui_root.size` 空间里做（F6 已经是这样）。触控层和 HUD 一起吃 inset。
7. **矩阵**：
   - 窗口 2400×1080、2340×1080、1920×1080；
   - touchScale 0.70、0.85、1.00、1.50；
   - inset {0、(48,0,0,0)、(0,0,48,0)}；
   - 新增：hudScale {0.80, 1.30} × minimapScale {0.75, 1.50} 的角点抽样。
8. **只改手机分支**：
   - 一切新几何都用 `_phone_factor() > 1.01`（布局）或 `touch_controls.visible`（触控）门控。
   - 桌面 1280×720 的现有 pin 原样通过。
   - 模态的手机布局用同一个门控切换容器参数，不另建第二套节点。

### B3. 模态 / 面板族的目标布局与交互规则

**通用规则 M0（手机模态缩放）**——替换 `_apply_ui_scale` 里“按 4:3 设计 + 高度裁切”的现状：

```
H_design   = 各模态固定设计高（≤ 430）
s_m        = min(s, (vh − 16) / H_design)        # 1600/1560/1280 宽都约 1.6
W_design   = min(W_max, (vw − 24) / s_m)         # 宽度随屏宽流动：20:9 ≈ 985，16:9 ≈ 785
```

- 面板用 `custom_minimum_size = (W_design, H_design)`，内部容器按宽度重排（HBox、Grid 的列数 = floor(W_design / 卡宽)）。
- 按钮高：手机分支统一 ≥ 52 设计 px（× 1.6 = 83 逻辑 px = 48 dp）。“small”按钮在手机上升级到 normal。
- 关闭/继续这类**主操作固定在右下**（右拇指）；破坏性操作（回主菜单、重置）放左上并保留两段确认。

### B6. 需要你拍板的决策

**D1 暂停入口放哪？**
- (a) 留在右手簇（现状），只放大到 70。
- (b) 点左上头像暂停，头像带 ‖ 徽。
- (c) 顶卡最右放一个独立 ‖ 按钮。
- **推荐 (b)**：头像本来就够大，有 125 px、远超 48 dp；顶角不容易误触；“点自己 = 看状态”的语义也顺。(c) 会挤占顶带宽度，s_t 掉约 0.08。

**D2 镜头辅助（aim）键**
- (a) 留在拇指簇。
- (b) 移到暂停快捷开关（设置里仍有）。
- (c) 合并到锁定键长按。
- **推荐 (b)**：它是开关，不是战斗操作，现在已经和设置项重复。(c) 引入长按语义，新手发现不了。

**D3 战力 6 片（pw-row）在手机上怎么处理？**
- (a) 只放暂停状态页，倍率变化时发 toast。
- (b) 常驻一个折叠片“战力 ▸”，点开展开。
- (c) 保留整行，缩到 s_t。
- **推荐 (a)**：它是战斗外信息，变化时会有提示，信息不丢。(b) 多一个点按目标，而且挤在顶带。

**D4 右列事件与目标**
- (a) 1 颗目标 pill + 抽屉。
- (b) 维持现在的栈 + 预算裁剪（徽改成可点）。
- (c) 把目标 / 事件搬到左上 hero 下方。
- **推荐 (a)**：右列和拇指簇的冲突从根上消失。(c) 左上下方是摇杆移动时左手视线的路径，也会压到中央跨度的左界。

**D5 原版的两行槽与物品栏**
- (a) 恢复招式 + 维生素两行槽；物品只放暂停页。
- (b) 两行槽 + 槽行上方再加一条物品小条（每件 28 设计，最多 10 件）。
- (c) 维持现状（只显示第 1 招）。
- **推荐 (a)**：补齐战斗相关的 parity（招式冷却），物品是战斗外信息。(b) 会把 Z7 顶抬高，摇杆 home 被迫上移，左拇指够不着。

**D6 给老玩家留不留“经典布局”开关（设置→界面）？**
- (a) 不留。
- (b) 留 1–2 个版本作为过渡，之后移除。
- (c) 永久保留。
- **推荐 (b)**：可以兜住肌肉记忆，又不让双布局长期加倍 gate 矩阵。经典布局 = 现在的 21.3.2 几何，gate 只跑 2400 s1.00 一个角点。

**D7 1920×1080（16:9）手机的地位**
- (a) 与 20:9 同等，阈值一样（必须进一步压缩顶带内容）。
- (b) 次一级，字号阈值放宽到 17。
- (c) 16:9 时顶卡改两行（计时单独一行居中）。
- **推荐 (b)**：Seeker 和主流机都是 20:9；(c) 会挤占中央栈的起点。
