2. P1 附带项（触控语义，与布局无关，本期一并做）：双拇指转视角——摇杆吞掉第一指后第二指拖屏转视角现在不工作（规划 A6/A9 已标）。直接处理 InputEventScreenDrag 做相机旋转，与摇杆触摸 ID 分开跟踪；能用 harness 双触模拟证明就证明，不能则给出代码路径证据 + 在 changes 里标注「待真机确认」。
3. 硬约束：①信息对齐红线——任何被隐藏/移走的值都必须有「一次点击可达」的新去处，且每期门里有断言实证（规划 B5 的 parity 陷阱逐条对照）。②C21.3 已立的规则凡规划未明说要改的一律保留（摇杆环钳制 600.65 界、槽位行位置、安全区接缝、提示行数断言等）。③包名/签名不变；reference/ 永不进包。④不要碰 DIFF.md 的 C22 段落与玩法代码（C22 刚落地，以其落地树为基线开工；开工前先 `git status`/文件时间确认树是静止的）。
4. 验证仪式照项目老规矩：VM 树是事实源 → `Test/sync_to_nuc.sh` 同步 + 树哈希对账 → NUC 上清 .godot 缓存重导入 → 跑门与 suite → 日志用 `Test/pull_from_nuc.sh` 按本期前缀拉回（c2132_ 式命名）→ bootsmoke。全部五期跑完后在 NUC 出一个 APK 拉回 VM 验签（证书 b05b80e1…a232、reference 计数 0、字节数+sha256 写进 changes 末尾）。
